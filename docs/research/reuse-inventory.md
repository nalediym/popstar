**What it is.** A delivery method for AI-native teams, shaped as a *graph* of waves, not a pipeline: DISCOVER → DIVERGE → DISCUSS → DESIGN → DEVOPS → DISTILL → DELIVER (→ EXAMINE). DISCUSS is PO-led and cuts value into **visible feedback increments** (slices a human can see and react to, never frontend/backend layers). DESIGN updates the *durable* architecture brief + ADRs, never a per-delivery plan. DISTILL writes an *executable public oracle* (acceptance tests through the real driving port, observed RED first). DELIVER makes it GREEN, then an independent reviewer and a source-blind EXAMINE, then integrate. The invariant: every feature ends DISTILL → DELIVER; you enter wherever your knowledge gap is (skip checklists in `~/Projects/nWave-experimental/docs/guides/wave-routing-and-entry-points/`).
- **DES steps** = the *Deterministic Execution System*: `des po|design|oracle|craft|verify|prepare-role|record-role-result|integrate|state|project`. DES constructs documents and records measured facts (RED/GREEN, candidate SHA, reviewer verdict); it never launches a model. The LLM orchestrates; `NEXT` is advisory; every step returns `Success | Refusal | Retry | Indeterminate` (`~/.claude/skills/nw-auto/SKILL.md`).
- **Durable authorities** (SSOT model, `docs/guides/understanding-ssot-model/`): `docs/product/{vision.md, jobs.yaml, journeys/*.yaml, architecture/brief.md + adr-*.md, kpi-contracts.yaml}` grow forever; a feature adds at most 6 delta files under `docs/feature/<id>/`; `feature-brief.md` is the one file written for humans and is *regenerated*, never hand-edited. Conflict order (`nw-buddy-ssot-knowledge`): code > config > declared SSOT > ADR > spec > generated doc > README > commit prose > memory.
- **Reviewer / examiner.** Every producer role has a read-only *reviewer* twin (adversarial, cites file/line, may veto but never repairs; missing evidence = INDETERMINATE, not approval; `nw-review`). `nw-user-examiner` is *source-blind*: it never sees design, prompts, tests or diffs, only the original Request, an **expectation charter** (intent · exact public start recipe · positive observations · one `Negative:` line, `nw-expectation-charter`) and public observations the caller captured. "A fix no one observed working is not a fix" (`nw-bugfix`).
- **Request S/M/L** = a working size label the LLM assigns and revises from evidence, never a route. Split into ordered Requests when values need different authorities or a late refusal would discard more than one value. The first value is the walking skeleton. Never walk two Requests on one repo at once.
- Two habits that earn their keep: the **visible baseline** (`Baseline: GREEN — <cmd> (<scope>)` before touching anything; a broken setup is not your intentional RED) and **completion claims the destination** (done = the revision is reachable from `main`, not "my worktree is clean"; `nw-cross-cutting-invariants`).

**Where the examiner sits.** Two gates. (1) After RENDER, before STITCH, per scene: a *fresh* agent that never saw the prompt, graph, seed or look sheet gets `outputs/scenes/<id>.mp4` (as a contact sheet + ffprobe) and the scene's promise from `shots.json` (set, wardrobe, emotion, "follows her motion", `Negative: skin lightened, a hand lost, mouth frozen`) and returns observations. (2) After STITCH, on `outputs/final.mp4` against Vision v2's three rules (cuts on downbeats, captions on lines, clones only in s4). The director / render skill never grades its own scene. Receipts go in `outputs/examine/<id>.json`.

**Five practices for the next 12 hours.**
1. Visible baseline every turn: `bun tools/popstar.ts status && bun tools/popstar.ts doctor` (+ `python3 -I tools/validate_shots.py shots/in-the-loop-devagar.json` once the coach build lands) → one line `Baseline: GREEN|RED|INDETERMINATE — …`. (`nw-auto` §"Visible baseline".)
2. Expectation charter per scene *before* `submit_batch`: 5 lines in each `scenes[]` entry or `outputs/charters/<id>.md` (intent, the exact `comfy_compile` + `submit_workflow` recipe, 3 positive observations, 1 `Negative:`). Then a source-blind examine: a fresh `Agent` (read-only on `outputs/`, told not to open `workflows/` or the skills). `nw-user-examiner` itself is `StructuredOutput`-only, so it needs bytes (contact-sheet PNG, ffprobe JSON) in the prompt, not paths.
3. Walking skeleton as one Request: "s3 anchored to its look, 8 s, stitched with captions" end to end before the 4-scene batch (HANDOFF step 3 already says this). Clones and the hybrid spike are separate Requests; do not run them in parallel on this repo.
4. Completion claims the destination: the "in flight" rows in HANDOFF are uncommitted lanes. A stage is done when its receipt exists *and* `git status` no longer carries it. Commit each landed build before starting the next.
5. Run the hybrid lip-sync as an `nw-spike`: one question, the evidence that flips the decision (mouth envelope tracks the vocal envelope *and* identity holds), budget 2 jobs / 30 min, fallback already named (pose-only). Nothing enters `shots.json` until the examiner saw it. Also ask the collaboration mode once (`/nw-mode-select`: interactive / final review / full delegation; silence is not delegation).

**What would slow a hackathon down.** `nwave-ai project enable` plus the DES loop: 10+ commands per value, `schema_version 2` JSON manifests, authority digests, `lanes/` worktrees, evolution docs, HTML projections (`nw-doc-as-artifact`); hours before the first render, and `des` is not even on PATH. Roles run `claude-opus-5` with `maxTurns 40` on 1.4k–2.6k-line definitions, each with a reviewer twin (2–3× tokens per value). The method template budgets DESIGN at 25 % of "2–12 weeks". Formal verification (Agda/TLA+), algebraic design, mutation and property-based testing lenses do nothing for a 32 s video. Do not enable nWave in this repo tonight: it writes `.nwave/` and there are target-hook installers (`~/.claude/scripts/install_nwave_target_hooks.py`).
